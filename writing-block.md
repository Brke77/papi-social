# 13. AUTHENTICATION VE SECURITY

Güvenlik sonradan eklenecek bir detay değildir.

Tasarımın başından itibaren güvenli mimari oluştur.

Gerçek modda Supabase Auth kullan.

Özellikler:

- Sign up
- Sign in
- Sign out
- Password reset
- Session persistence
- Protected routes
- Server-side user authorization

Şifreleri kendin veritabanında saklama.

Supabase'in güncel ve önerilen SSR yaklaşımını kullan.

Önemli kurallar:

1. Service-role veya secret key tarayıcıya gönderilmemeli.
2. API anahtarları Git'e eklenmemeli.
3. Gerçek secret değerleri kaynak koda yazılmamalı.
4. Her kritik işlem için server/database authorization yapılmalı.
5. Kullanıcı başka kullanıcının postunu silememeli.
6. Kullanıcı başka kullanıcı adına like veya comment oluşturamamalı.
7. Bookmark listeleri başkaları tarafından okunamamalı.
8. Bildirimler sadece alıcıya açık olmalı.
9. Moderation işlemleri gerçek rol kontrolü gerektirmeli.
10. API tarafında input validation uygulanmalı.
11. XSS riskleri azaltılmalı.
12. Rate limiting stratejisi uygulanmalı.
13. Hata mesajlarında gizli bilgiler sızdırılmamalı.
14. Dosya yüklemelerinde gerçek dosya türü ve boyutu doğrulanmalı.
15. Yetkisiz kullanıcı veri yazamamalı.

## Row Level Security

Supabase'te istemciye açık tablolarda uygun RLS ve minimum gerekli veritabanı yetkilerini yapılandır.

SELECT, INSERT, UPDATE ve DELETE politikalarını ayrı ayrı düşün.

`auth.uid()` ile sahiplik kontrolleri uygula.

Özel veriler için deny-by-default prensibini kullan.

RLS politikalarını yalnızca yazmakla kalma; izin verilen ve reddedilmesi gereken senaryoları test et.

Recursive veya çelişkili RLS politikalarından kaçın.

## Media Security

Fotoğraf yükleme için:

- Sadece izin verilen formatlar
- Dosya boyutu sınırı
- MIME ve gerçek içerik kontrolü
- Rastgele / güvenli dosya adları
- Sahiplik tabanlı storage path
- Uygun bucket erişim politikaları
- Gerektiğinde signed URL
- Silinen içeriğin dosya temizliği

Yükleme işleminde hata olursa kullanıcıya düzgün bilgi ver.
